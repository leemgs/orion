# CPU memory-hierarchy probe — measured data

These files were generated by `experiments/cpu_hierarchy_probe.py` on the CPU
identified in `cpu_hierarchy_summary.json`. They are measurements, not simulated
or modelled output.

## Protocol

- The script auto-detects the last-level cache from Linux sysfs (48 MiB in this
  run) and records the source and software/hardware metadata.
- NumPy constructs a seeded single-cycle random permutation.
- A C11 kernel compiled with `-O3` performs dependent loads and times the loop
  with `clock_gettime(CLOCK_MONOTONIC_RAW)`, avoiding Python-loop overhead.
- Working sets span 0.5–256 MiB; every point has one warm-up and seven retained
  trials. No outlier was removed.

## Interpretation

Mean time per dependent load increased from 6.8 ns at 0.5 MiB to 169.7 ns at
256 MiB. Intermediate points are non-monotonic, and the experiment does **not**
show a discontinuity at the manuscript's conventional `R_C=0.5` label. Cache
levels, address translation, virtualisation, scheduling, and frequency are
potential contributors.

This is a single virtualised CPU experiment. It is not evidence for GPU/TPU
DMA behaviour, an `R_B` boundary, strategy inversion, classifier accuracy, or
cross-platform generality.

Reproduction requires a C11 compiler available as `cc`, Python, and NumPy.
The compiled shared object is cached in the operating system's temporary
directory and is not written into the repository.
